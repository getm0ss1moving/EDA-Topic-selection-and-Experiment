## Coordinator findings from R0

1. **Packet envelope was not hash-covered (real defect, fixed here).** `ASSIGNMENT.json` is generated by the exporter and sits inside the packet, but the first exporter revision did not hash it. Every actor reported the gap. `scripts/project.py` now records its digest under the manifest `generated` map.
2. **The allocation run manifest named the wrong input commit (real defect, recorded here).** `runs/DSK-ALLOC-0001/manifest.json` records `67fb73b`, which is the pre-allocation base, while the packets were exported at `252a5c8`. The allocation manifest's `input_commit` is a provenance label for that run, not a packet identity; the packet identity is the `PACKET.json` digest above.
3. **The executing model was not the requested model (real, unresolved).** This host exposes no per-agent model override, so all 21 onboarding runs executed on `deepseek-flash` while the registry requests `deepseek-v4-pro` at `max` for proposers. Actors detected and reported this themselves; it is recorded in `config/agents-deepseek.json` as an open operator decision. The proposer tier is unexercised.
4. **One actor misreported its own packet inventory.** `DeepSeek-P05-TIMING` recorded the packet as 47 files on disk with 7 outside the allowlist, naming `docs/DEPLOYMENT.md`, `docs/FORMATS.md`, `docs/GITHUB.md`, `docs/LAUNCH.md`, `docs/TEAM.md` and `config/agents.json` as unlisted. All six are in fact manifest-listed. The audited packet contains 42 files, of which exactly `ASSIGNMENT.json` and `PACKET.json` are unlisted. The same actor's per-file SHA-256 table (40/40) is correct, so this is a reporting defect in an environmental observation, not a hash-integrity failure. Recorded as a data-quality finding and deliberately not corrected in place; it is the kind of claim a verifier round must check rather than trust.
5. **No other packet file mismatched.** All 21 actors reported 40/40 manifest files matching by SHA-256, 0 mismatches, 0 missing.
6. **Isolation is policy-level only.** Every actor recorded that the enforced boundary is a path allowlist plus a separate outbox, not an OS sandbox, on a shared host with `danger-full-access` and one GitHub credential.
