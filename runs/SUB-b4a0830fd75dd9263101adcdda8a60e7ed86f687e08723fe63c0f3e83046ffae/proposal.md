## Concrete anchor-preserving refinement

Keep operation-specific exact world classes, dependency intersection, split and exact result re-coalescence. Specify their administration instead of claiming a new primitive. For each operation input i, retain the immutable base value b_i and a sparse map E_i from worlds whose exact input differs from b_i to their input values. E_i is certified from **computed exact state**, not predicted reachability or equality. Let U be the union of these supports.

1. Outside U, the complete input tuple is the base tuple; evaluate it once if the complement is nonempty, reusing a valid epoch-local result when available.
2. Within U, gather each world's exact parent tuple by sparse lookup. Intern identical tuples using full equality; evaluate each distinct tuple once. Coalesce equal results, retaining a default value plus explicit exceptions and complete statuses.
3. Choose this support traversal, ordinary compatible-class lifting/MTBDD, or dense world-to-tuple traversal from already available support/class cardinalities and a frozen cost rule. No unseen test output or future trace may drive a deployable choice. Charge map creation, gathering, hashing, conversion, intersection tests, default complement handling, scheduling and retained bytes.
4. At a byte cap, retain or recompute immutable state with reference-count liveness; charge every recomputation and key rebuild. Compare FIFO/LRU/cost heuristics and the same controller transplanted into conventional lifted execution and keyed memoization. No extra memory or privileged feature for the proposal.

If all nonbase values coalesce to the base output, the exception map becomes empty. This is a representation of complete outputs, never authorization to omit output reads. Eventually serialize or serve all declared entries; charge that identical consumer endpoint to every baseline.

For d inputs and n worlds, this **conditional cost model** separates class-product work prod(c_i), dense tuple-gather work O(d*n), and support work O(sum|E_i| + d*|U|), before exact primitive evaluation, output building, hash/equality/bitset costs and engine work. Default values must already be available or their computation is charged. These are ordinary alternative enumeration/join strategies, not a new complexity result against optimized variational execution. Maintaining a complete sparse support may itself require O(d*n); no saving is claimed when it is reconstructed that way at every operation. The proposed systems question is whether naturally propagated, already-needed timing partitions make this support inexpensive enough under a real memory limit.

The candidate contribution is a measured **administration/memory/recomputation tradeoff in a complete exact STA adapter**, possibly aided by learned representation/admission selection. The sparse gather kernel itself is conventional, and its identical implementation is a mandatory baseline. If both systems expose identical sufficient state and share the same kernels/controller, they are the same tested mechanism: report parity, not an EDA novelty claim. No representation-only theorem can rescue the topic from that outcome.

## New analytical evidence and limits

A02 (experiment-plan.md) publicly embeds exact Python code, parameters, compact stdout and hashes. It checks 768 seeded random integer cases plus five named controls. All exact outputs and cold unlimited complete-key primitive counts agree across independent evaluation, keyed memo, compatible Cartesian lifting and support traversal. The conventional sparse join is deliberately the same kernel and matches identically.

In the constructed n=256,d=4 disjoint-support case, class-product traversal attempts 6,561 products while support traversal probes 33 tuples after reading 32 support entries; both make 33 primitive calls and materialize 256 output entries. Dense-binary inputs reverse the proxy advantage: 16 class products versus 241 support tuple probes plus 512 support entries. These heterogeneous counts are not time units, and the Cartesian baseline is explicitly unoptimized. Aligned distinct tuples expose empty-product overhead; n=1 and full re-coalescence preserve negative controls. The fixture demonstrates crossover conditions and equivalence, not timer realism, runtime, bytes or statistical gain.

Equal pure keys with sufficient cold cache imply identical unique primitive-call counts for memoization, conditional lifting and this construction. At finite capacity, differences require an explicit schedule/eviction trace and charged storage. With common primitive cost C, remaining administration A_j and reporting/restore R_j, T_j=C+A_j+R_j; net advantage requires reducing A+R including all proposal overhead. If a genuinely shared irreducible reporting/restore floor is fraction f of baseline time, even removing all other work yields fractional time reduction <=1-f. Hence f>0.8 precludes the provisional 20% screen in that restricted accounting model. This is an algebraic gate; f is unmeasured and not assumed common in a real implementation.
