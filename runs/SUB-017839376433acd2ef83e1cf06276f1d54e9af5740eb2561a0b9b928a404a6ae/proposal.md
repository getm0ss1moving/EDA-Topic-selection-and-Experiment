## Concrete causal advance: distinguish gathering from lifetime

Define state at operation v as (base-valid flag, exact base value, complete-key to world-membership map, full value/status classes, remaining declared consumers, epoch). Q gathers complete tuples by base plus certified exceptions; conventional B5 gathers or joins the same exact tuples and is allowed the identical sparse kernel. Both evaluate each requested key once, coalesce identical full results, decrement the same consumers, and release at the same last use. A bijection maps each Q (operation,key,membership) record to B5's same record; preserving dependency edges, pure functions and scheduling decisions preserves this normalized transition graph by induction. This conditional correspondence does not equate actual map-construction cost, engine memory or wall time.

A03 separates two counterfactuals on a declared reconvergent DAG with all outputs retained. Changing B5 from retain-all to ordinary last-use reclamation changes the logical storage peak from 1120 to 688 bytes. Q with last-use is also 688, and Q/B5 normalized traces agree. These are a specified logical encoding, not process bytes; graph/base/key/controller metadata and temporary implementation buffers are outside the model. Consequently the observed modeled storage reduction belongs to lifetime scheduling shared by both methods, not to world partitions uniquely. No eviction, byte-cap solver or rematerialization is implemented or claimed by this fixture.

Gathering has a different accounting result. On the same fixture Q makes 56 dense reads to construct supports, retains 28 support entries and performs 28 sparse tuple reads; B5 performs 56 dense tuple reads. These counts have different units and no calibrated time weights. They expose why claiming support-gather savings while omitting support creation is invalid. A defensible future delta must avoid or amortize maintenance cost through an identified interaction that an equally informed conventional executor cannot already obtain at the same cost. If it is simply a specialized representation or policy available to B5, attribute the contribution there and test that useful system without claiming a separate Q structure. We have not established that useful system's novelty or need.

A03 also tests 480 finite integer operation cases (459 with no requested base tuple), an independent base not taken from world zero, total output coalescence, distinct error-status identity and invalid-default dense fallback. It charges five base evaluations separately from 20 requested primitive calls and materializes 16 output entries in the named DAG. This is own analytical observation only; no STA speedup, implementation correctness certificate or calibrated forecast follows.
