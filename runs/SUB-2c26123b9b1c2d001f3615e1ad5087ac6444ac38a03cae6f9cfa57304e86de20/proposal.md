## Scope and reference contract

Freeze one sweep order, candidate list including KEEP, LR multipliers, leakage weight, local-neighborhood definition, timing model, candidate guard predicate, tie order and commit hysteresis at an immutable query epoch. For each candidate c, a reference adapter R refreshes every dependency read by that declared local evaluator and computes scalar J(c)=leakage(c)+sum_e w_e*d_e(c), plus cap/slew and compatibility guards. The winner is the lexicographically ordered minimum feasible J; return its exact reference score and guard status. This local choice may be heuristic for global PPA even when replicated exactly. No equivalence to full-signoff ECO optimization is implied.

Initial prospective model: acyclic combinational data paths, fixed topology and parasitics during a query, single declared max/setup scene, scalar NLDM interpolation within audited legal table domains. ## Causal mechanism: compare alternatives under the same boundary state

Let z be the shared, candidate-independent boundary state of a query, and Z a sound enclosure of its current value obtained from a complete, charged dependency update. Distinguish this deterministic computation uncertainty from fabrication/process randomness. For candidate c and feasible incumbent b, bound the *paired difference* D_cb(z)=J(c,z)-J(b,z), retaining the same symbols for common upstream/slew/load effects. Candidate-dependent internal loads and downstream effects remain distinct expressions; they must not be cancelled merely because they share a net name. Build the paired expression from the audited candidate dataflow, not from two independent absolute ranges.

A relation lower(D_cb)>0 can eliminate c only after b's feasibility is known and the bound covers every current boundary realization. Strict comparisons avoid silently reversing ties; overlapping/zero differences are refined or evaluated by R. A tournament may start with exact-feasible KEEP; when KEEP is infeasible or no exact-feasible incumbent exists, use R until one exists. Resolve all candidates that might beat the incumbent, then materialize the final winner's exact J and guards. Unknown guards may be bypassed only for a candidate already strictly dominated by an independently feasible incumbent; otherwise compute the reference guard. Final acceptance/hysteresis uses exact baseline and winning scores. A whole-sweep reference timing check remains charged.

The system hypothesis is that candidate-relative correlation can prune more exact *refresh work* than absolute bounds while preserving the declared choice. It must be cheaper than obtaining the precise boundary state and scoring candidates directly. Z is not free: propagation, negative queries, context, provenance, table region construction and invalidation all count. In the important countercase where the boundary is already precise and LUT calls are cheap, ordinary exact evaluation can dominate; do not manufacture uncertainty to justify this mechanism.

For the initial NLDM subset, overlay candidate table breakpoints and any shifted upstream-load breakpoints before bounding the difference. Within a common bilinear region, simple extrema arguments apply only when the expression really is multi-affine in independently ranged boundary coordinates. Composed slew propagation, max branches and correlated internal nodes generally destroy that property. Use validated affine/remainder enclosures or refine/fallback; a vertex-only test of the full composed circuit is unsound. These are implementation obligations, not a completed engine proof.

Conditional selection lemma (own reasoning): if current true z lies in Z, all compared relations enclose the corresponding reference differences with its arithmetic semantics, an incumbent is reference-feasible, and every discarded alternative is strictly more costly, discarding them cannot remove the reference minimum. This is an elementary branch-and-bound fact, **not** new mathematics or proof that cheap sound Z exists. Equal pure-key caches can still eliminate repeated exact primitives; no extra primitive-count saving over such a cache is assumed.
