# Engineering gap and adoption boundary

The target user is a timing-optimization developer comparing mutually exclusive legal cell-size alternatives from one checkpoint. S01 pp.14–15 and 18–19 documents that workflow; S03's pinned Resizer functions expose present undo/parasitic/timing integration. Neither proves that large repeated-state batches occur in the proposed restricted domain today. EXP-001 must identify a real public caller and its actual context distribution.

OpenSTA S02 already advertises query-based incremental delays/arrival/required updates. OpenROAD S03 already journals ECOs and restores parasitics/timing. S04/S05 indicate longstanding shared control flow and exact timing-result reuse. Therefore an open implementation feature gap, if one is found, is an integration gap until a useful new capability/tradeoff is demonstrated against faithful composition.

Public commercial evidence is limited. The accessible Synopsys mode-merging search extract S17 advertises scenario reduction for STA/ECO; the current HTML was 404 and PDF 403 in this session. No commercial implementation or quantitative result was verified. Patent disclosures S04/S05 are mechanism evidence, not proof of today's shipped capabilities, freedom to operate or performance. No commercial-tool license or signoff comparison is established. No claim that production tools lack mask compression is made.

Matched experimental conditions: fixed base/design family, identical legal alternatives and caller decision, one explicitly supported scenario, same numerical kernels/FP environment/inputs, equal cache memory and core count, same output expansion and fallback contract. Incomparable without further work: post-CTS MCMM/hold, SI/POCV/CPPR, new topology, final routed changes or foundry signoff. The ISPD 2027 evaluator's BC/TC/WC setup/hold flow (S14) highlights the coverage gap; its problem must not be advertised as solved by an ideal-clock single-scenario result.

Adoption cost includes read-set instrumentation, pure-kernel boundaries, stable context IDs, graph invalidation, shared-output lifetime/GC, load recalculation, report fidelity and final-context checking. If these dominate or real incremental cones contain mostly unique states, the mechanism has no established engineering advantage. Downstream acceptance means the same caller decision at lower fully charged total iteration cost, with the same full-context guards. Faster toy propagation or lower RMSE is not evidence for closure improvement.
