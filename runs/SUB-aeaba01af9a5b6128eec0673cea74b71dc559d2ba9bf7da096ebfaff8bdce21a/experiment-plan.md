## Hypotheses and endpoint

H1 is the full-cost candidate-selection hypothesis in proposal.md. Primary diagnostic phase: time to complete the same exact validation of a frozen repair-candidate subset and the best checked candidate quality versus elapsed cost. For deployment closure, repeat the same bounded sibling-pool decision after each accepted checkpoint, regenerating candidates by the identical pinned procedure in every arm. Each pool is fixed before its subset selection; all prior history, regeneration and accepted-step costs count against one global deadline. Stop at full clean/connected target, exhausted legal candidate space or deadline. This is not a free adaptive-generation advantage for the proposed arm. Deployment endpoint: wall time to a complete, connected, engine-DRC-clean route meeting baseline post-route WNS/TNS and no-new-hold constraints at fixed die, netlist, technology, SDC and corner. Report failure/timeout probability, final total and per-rule markers, opens/shorts, WNS/TNS, wirelength/vias, runtime and peak memory. WNS may not regress beyond independently measured numerical repeat tolerance; that tolerance and the meaningful wall-time saving threshold remain UNVALIDATED. They must be frozen from baseline variance and engineering input before candidate results; otherwise report descriptive diagnostics only. Do not transfer D05's provisional 20% threshold or the predecessor's +0.02ns as an owner mandate for this new problem.

## Exactness and candidate control

Bind initial physical DB/netlist/LEF/rules/SDC, reference executable/config hashes, seed/thread policy and baseline whole-design marker/connectivity outputs. First implement only finite-radius Manhattan same-layer spacing. Every other rule is checked by complete selective reference dispatch if source-audited, otherwise full reference fallback; spacing-only cannot imply full clean. If fallback unconditionally repeats all work on every candidate, do not claim cached spacing saved the repeated full pass; report the overhead and stop unless a sound complete dispatch interface is established. Such an interface is a missing prerequisite, not implemented capability. The physical enumerator must account for insertions, deletions, range nonmatches, net changes, derived objects and boundaries, and preserve every unchanged baseline violation. Compare canonical complete marker sets, not only counts. Final full checker and connectivity guard run on the exact exported final geometry, whose hash accompanies extracted QoR. Native repairs/retries are allowed only if their actual delta is recorded and final reports/export regenerated. This adopts the released predecessor C-T301 lesson without alleging a present defect.

Full reference and candidate branch start in clean, separately initialized processes. Before any in-memory optimization, show bit-/semantics-equivalent final outcomes and markers on repeated identical inputs and retry fixtures. Otherwise retain process isolation and charge it. A crash, missing report, interrupted or timed-out check is UNKNOWN/censored, never feasible or a fabricated bad QoR label. Failing spacing or connectivity is FAIL. All candidate attempts, including abstentions and fallback, count in cost and denominator.

## Baselines and attribution

B0: full reference checking for every candidate with fixed deterministic order and no cross-candidate reuse.
B1: strongest faithful native incremental per-net checker/queue adaptation, preserving its final full check.
B2: same exact obligation cache, ordinary fixed order; conventional spatial/hierarchy pruning and safe hashing enabled.
B3: same cache plus marginal verified-benefit/new-work greedy, coverage-greedy, and bounded beam/exhaustive pair search using the same available inputs. Compare all and validation-select strongest before held-out runs.
B4: same-feature separate benefit, cost and overlap predictors plus ordinary fusion, using B3 controller.
B5: shared-trunk multitask predictor and direct set-value predictor with matched labels, parameters/search compute and B3 controller. Architecture equality or ordinary reparameterization is an identity control, not an opponent required to lose.
B6 candidate: pair selection guided by predicted shared obligation work and terminal value; exact validation/fallback identical to B2–B5.
B7: centralized and two-specialist controllers with identical observations, invocations, seeds and tie rules. They must match when they implement the same policy. Extra LLMs are not a scientific contribution; an optional LLM arm requires a distinct future API/token allocation and single repeated-call plus parallel-search controls.
B8: generic dependency/memoization adapter and a DRC-Aid-style bounded-edit/verification/state-memory adaptation on the same digital candidate pool, if primary code and licenses allow a faithful implementation. If adaptation is impossible, publish limitation and do not claim superiority to original systems.
Offline clairvoyant subset enumeration may use true future obligations/outcomes only as a labelled headroom bound for <=16 candidates. It cannot be a deployable model input or an equally informed baseline.

Compare full policy and core-only diagnostics; cache construction or learned-quality advantages must not be confused with better candidate generation or extra evaluated candidates. B2–B6 share exact cache capacity/contents, fallback, candidate pool, metadata computation and oracle. Charge learning amortization explicitly: total setup C, per-decision saving delta; break-even requires delta>0 and N>C/delta. No numerical break-even forecast exists.

## Statistics and falsification

Preregister paired cases and at least five seeds if any component is stochastic; deterministic adapters use repeats to estimate machine noise. Three families is an initial floor, not a power calculation. EXP-005 estimates paired variance, then freezes sample sizes, confidence intervals, multiplicity policy and effect threshold using baseline-only data. Primary unit is family, not correlated candidate count. Report all failures, right censoring and time-to-target curves, with separate label/preprocessing/model/fallback budgets. Freeze candidate-generation stop rule and seed schedule before outcome collection; no selection on easy markers.

Stop certification on one cached/full-oracle disagreement; quarantine output and repair before reconsent. Stop learned-architecture claim if direct/fused models or strong B3/B8 recover the same frontier at equal cost. Stop scheduling claim in the all-candidates/unlimited-cache regime, where union work is order invariant. Stop usefulness claim if cache maintenance/fallback/training cost exceeds savings or if timing/connectivity/route quality degrades. A negative pilot informs rejection/parking, not a hidden pivot to cache-hit rate.
