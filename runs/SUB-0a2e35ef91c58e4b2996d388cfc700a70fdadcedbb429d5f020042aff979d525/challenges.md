The release does not yet define an observation projection/likelihood connecting these different objects, nor a zero-support posterior rule. EXP-104 acknowledges future interface/configuration work, but a node cap alone cannot specify this update.

**Evidence and reasoning bridge:** C2-S02 §2 defines conditional observation rewards and distinguishes reward penalties from budgets. Full exact-payload equality is necessary for cache reuse but need not be the observation model used for uncertain planning. Conflating them would either leave a posterior undefined or introduce undeclared approximate assumptions.

**Required repair:** freeze the query schema, deployable observation projection, likelihood/weight update, finite-support miss handling, and termination/fallback; specify cost units separately for utility penalty, elapsed deadline and node accounting. Use the same observed evidence and update semantics in C/E/F while permitting declared learned distributions to differ. A conservative STOP/whole-reference fallback is an acceptable implementation if its paid work and frequency are counted. Approximate likelihood must never authorize exact reuse.

**Confidence/uncertainty:** high that these fields are absent in the current research specification; conditional that a real implementation would encounter the witness. No physical frequency is asserted. **Reversal:** an explicit total update function handles all API outputs with normalization or declared fallback, together with same-input controls and no approximate certificate acceptance. **Cheapest decisive test:** source-only schema plus own finite tests for observed/new payloads, empty ranges, unseen cost bins, unequal observations with equal planner abstraction, and zero-weight collapse.
