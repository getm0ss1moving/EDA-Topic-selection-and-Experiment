Demand validation is blocking T02: obtain an owner/practitioner judgment on whether +0.02 ns matters at the selected clocks and whether rerouting is preferable to sizing/buffering in this exact fixed-netlist case. Record clocks and slack normalization. No response is fabricated. Integration entails a C++ router hook, transactional checkpoint support and full extraction/STA; a shell wrapper alone cannot be assumed to provide selective routing. No silicon, advanced-node, MCMM or manufacturing-signoff claim is planned.

An open-source feature omission, code availability and low GPU demand are implementation context, not a scientific gap. If equal-budget existing repair already reaches the endpoint, the contribution is unsupported even if our implementation is convenient.
