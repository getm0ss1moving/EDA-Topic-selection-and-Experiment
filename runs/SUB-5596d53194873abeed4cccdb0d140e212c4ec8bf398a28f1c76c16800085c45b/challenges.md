## OBJ-001 — The decisive comparison currently lacks an operational treatment difference

Target: CLM-009; proposal “Mechanism and invariants” steps 1–6 and “Nontrivial combination test”; experiment-plan “Controlled comparisons” B3/C and H2; tasklist EXP-005/007.
Severity: major, fixable before a causal experiment; confidence: high about present underspecification, unresolved about eventual usefulness.
Evidence: the frozen release gives B3 the same action-conditioned O(X), occupancy/connection predicates and finite/MILP solve as C. C's specified steps generate those options, solve that table and verify the combined edit. No different option-generation schedule, reusable inference, pruning invariant or realization procedure is specified for C versus the monolithic B3. This is direct source evidence from the exact released text, not a claim about inaccessible literature.

Reasoning: for fixed checkpoint, candidates, options, admissibility predicates, objective, oracle and tie-breaking, both methods optimize the same feasible set. If their oracle order is also identical, their transcripts and accepted incumbent are identical by induction. If order or lazy generation differs, equal finite tables still do not imply equal bounded-time behavior—but that different executable rule is precisely the missing treatment. Comparing module names cannot isolate CLM-009. This is a same-assumption conditional reduction, not a theorem that all implementations have equal runtime. If B3 is intended only as an oracle/equivalence control, failing C whenever that oracle agrees is an overly strong novelty criterion: equal answers can coexist with a useful cost/reliability contribution.

Applicability: the reduction is to the proposal's own B3, not to all industrial tools. It applies only when information, feasible alternatives, objective, tie-breaking, oracle sequence and resource treatment match. CP-001 and CP-002 establish adjacent conventional mechanisms, but neither proves the full post-CTS action interface is already published. No mathematical novelty or super-additivity is demanded.

Cheapest decisive test: before physical execution, produce side-by-side B3/C pseudocode and a deterministic mocked-call trace specifying option-generation, subset scheduling, realization and stop behavior. Either exhibit the first differing operation and the claimed useful cost/capability consequence under identical inputs, or label B3 an equivalence oracle and formulate the actual systems delta against a faithful existing composition. Keep option-generation cost visible even if options are shared for the selector-only test. An analytical trace is enough at this stage; no measured PPA gain is required.
Reversal: withdraw if the next frozen revision identifies a meaningful executable difference with a falsifiable cost/capability prediction, or correctly reclassifies B3 and supplies an appropriate strongest practical comparator. Do not weaken B3 artificially, add privileged features or attach an LLM just to create a difference.
