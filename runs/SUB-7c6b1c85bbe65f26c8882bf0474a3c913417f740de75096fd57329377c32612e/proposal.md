## Problem and engineering decision

A detailed-routing developer must select mutually compatible short pin-escape routes before general path search. The concrete decision is whether a compiled, reusable state graph can answer the **actual finite set of route-enabling feasibility queries in one invocation** faster than an incremental SAT engine, while preserving all declared conflict constraints and the final chosen route geometry. Placement, netlist, library cells, track phase, fixed geometry and routing guides stay fixed. There is no cell movement, network-owner release, post-route timing repair, ML model or agent controller.

General need is supported by P02's introductory discussion of repeated pin-access analysis, not by a measured deployment pain report from this repository. Candidate-specific demand is unknown. A faster solver is useful only if total detailed-routing latency improves enough to matter. A **proposed**, unvalidated screening threshold is 5% total detailed-routing wall-time reduction relative to the stronger native/controlled FastPass baseline, with identical final route geometry in the controlled comparison and no worsening of connectivity, rule violations or extracted timing in deployment. The threshold and absolute seconds saved need practitioner validation (T02); they are not owner requirements or permission to run. The brief's +0.02 ns WNS screening threshold is not falsely claimed for this latency mechanism. Any change to the primary endpoint needs explicit preregistration before execution and independent review.

## Scope, inputs, outputs, correctness oracle

Input: a frozen finite domain D_i of candidate routes per pin i; unary forbidden routes from fixed obstacles and an enabling mask; a complete symmetric negative pair-conflict relation C; route geometries and identities; deterministic pin/route order. These may be exported from P05's pinned implementation after its existing preparation. Candidate generation and physical checking are common to all controlled arms. Empty domains and unsatisfiable connected components remain failures, never silently repaired.

Output: SAT/UNSAT/UNKNOWN for each declared mask, plus a canonical one-route-per-pin witness for the final satisfiable mask. UNKNOWN is mandatory on limits. Within the pure negative-conflict model, a solution selecting at least one route per pin can be reduced to one by deleting extras; hence feasibility matches P02's at-least-one encoding. This does not preserve arbitrary union-geometry objectives, feedthrough connectivity or rules requiring positive support from multiple chosen routes. Such predicates are out of scope and must be detected before claiming model equivalence.

Oracle layers: exhaustive assignment enumeration on bounded synthetic instances; independent SAT encoding on the identical exported graph; an independently configured geometry checker and connectivity checker on emitted access metals; complete deterministic detailed routing plus full-design extraction/STA for deployment guardrails. Graph agreement alone establishes no foundry signoff. Official contest checkers depend on a commercial tool (P08/P09); no license is established. The current Nangate45 GCD fixture is not representative evidence of pin-access stress.

The only proposed distinction is a **representation**: retain the effect of a prefix on every remaining route domain, rather than the identities of every selected prefix route, and retire a signature coordinate only when it can affect no future pin. This could compress many different selected-prefix assignments with the same remaining forbidden options. It is not an expressivity advantage over SAT or bucket elimination. Basic residual-function merging/decision diagrams may already subsume it. A useful engineering implementation alone is insufficient scientific novelty. ## Analytic failure fixture and nonclaims

Let ordered pins A,B,C,D have domains A={a0,a1}, B={b}, C={c}, D={d}. Only conflict is (a0,d); costs a0=0 and a1=1. The unique valid completion uses a1. A model storing a single cheapest prefix per last-two-route state keeps (a0,b,c) instead of (a1,b,c), although their future feasibility differs. A final validation can reject the cheaper completion but cannot recover an already discarded prefix without additional search. This is an elementary abstract counterexample to that restricted state representation. It is neither a reproduced PAO failure nor evidence that a legal technology/standard-cell fixture realizes the graph. PAO has retries and final validation; P02 and exact generic methods solve this fixture. T03 must test realizability/incidence and must not sell a synthetic contrast to an obsolete baseline as headroom over FastPass.

## Mechanism: exact residual-domain quotient

For a valid prefix S after pins1..k, define B_j(S)={v in D_j: some u in S has (u,v) in C} for each j>k. Let sigma_k(S) be the ordered tuple of these bitsets, omitting immutable empty entries only with the omitted-index schema in the key. The frozen graph, pin order, route identities and technology context are part of the compilation key. Two prefixes merge iff their exact sigma matches; hashes accelerate lookup but full key equality resolves collisions. For feasibility retain one representative; for an additive internal objective retain the lower-cost representative, with lexicographic route-ID tie breaking. The deployment comparison uses feasibility and common canonical witnesses, not a new surrogate objective.

A transition choosing v in D_(k+1) is admissible iff v is enabled by the query mask and v notin B_(k+1). Its next signature unions the conflict neighborhoods of v into future bitsets. A coordinate is retired only after its pin has been processed. Equivalent continuations may merge even if selected frontier assignments differ. Construct the base DAG without query-dependent pruning so later enable masks can be evaluated safely. A query disables route-labelled transitions, then backward reachability and lexicographic traceback find the canonical witness. If construction itself used a restrictive mask, it cannot answer later relaxed masks. Geometry/route-domain changes invalidate the DAG; no cross-incumbent or unchecked track-phase reuse is permitted.

Proof of CLM-008: for any fixed suffix T assigning one route to each future pin, prefix–suffix compatibility is precisely that each selected suffix route avoids its corresponding B_j. Suffix–suffix conflicts are independent of the prefix. Equal bitsets therefore give identical feasible suffixes. The transition union preserves the invariant by induction. Additive cost dominance follows only if future costs do not depend on the forgotten prefix; otherwise include their sufficient state or reject that objective. This is standard continuation equivalence, not an original theorem.

The state count can still be exponential. If active future bitsets contain m remaining route bits, there are at most 2^m signatures, often a useless bound. Assignment-frontier enumeration has a product-of-domain-sizes bound; neither bound universally dominates. Sparse conflict graphs need not have low width. Fixed rule-interaction radii and repeated library cells do not by themselves prove small signatures. No polynomial-time claim or theoretical saturation claim is made. A proposed cap of200,000 states/component or512 MiB compiler memory yields UNKNOWN plus an exact incremental-SAT fallback, with all wasted work charged; this fallback is conventional safety, not a contribution.

## Causal tests and strongest alternative explanations

H1: residual-profile merging, rather than a better conflict extractor, weakened objective, extra query repetitions or faster coding language, reduces solver work enough to lower full-route latency. H0: native incremental SAT already decomposes the problem sufficiently; compilation is generic memoization with no nontrivial new structure; preprocessing/downstream time dominates; or signatures explode.

Compare native P05, controlled same-query incremental SAT, generic min-fill variable elimination, the proposed quotient, and its exact no-quotient frontier ablation. Share graph/candidate preparation, active masks, canonical final witness, thread count, toolchain and physical conditions in controlled arms. Also compare against the unmodified native arm including any canonicalization overhead; a controlled win that loses to native is not an engineering win. Use actual native query counts, not invented repeated workloads. No reuse across changed geometry is credited. Evaluate abstract exactness separately from downstream physics.

CLM-009: let G be common preparation, S actual baseline solving over the actual invocation sequence, R downstream routing/oracles, K compilation and Q compiled-query evaluation, including canonicalization. With identical downstream geometry and deterministic work, T=G+S+R and T_new=G+K+Q+R. Saving=(S-K-Q)/T <= S/T. If S/T<the predeclared required total saving, no solver-only implementation can meet it in this matched model. This is a conditional upper bound, not a measured plateau. If downstream geometry differs, R need not match and the bound is inapplicable; then measure full flow and explain the changed mechanism rather than attributing arbitrary route quality differences to speed.
